# DailyFit V1.0 最终产品需求文档

> 需求状态：已确认；版本：V1.0；平台：Android 原生应用、个人使用、本地存储。

## 一、产品定位
DailyFit 是一款个人日常管理与健身记录 App，将日常习惯、临时任务和力量训练整合在一起。核心目标：帮助用户建立并坚持日常习惯；管理每周固定训练计划和每日临时调整；详细记录实际训练过程，包括动作、组数、重量和次数；保存历史数据，帮助用户回顾长期成长。产品原则：简单、清晰、可靠，优先保证数据记录准确。

## 二、技术方案
| 项目 | 技术 |

| 开发平台 | Android |

| UI 框架 | Jetpack Compose |

数据全部保存在本地，不需要账号、服务器和云同步。

## 三、页面结构
底部导航栏三个页面：
- **首页 Home**：今日固定习惯、今日临时任务、今日训练安排、各模块完成进度、完成任务后的鼓励弹窗。
- **计划 Plan**：固定习惯管理、完整训练计划库、每周训练日程、单日训练安排、独立动作库管理与搜索。
- **历史 History**：历史习惯打卡、历史训练记录、训练数据统计；体重变化曲线后续扩展。

## 四、核心功能需求

### 4.1 日常习惯管理
用户可以创建、修改、停用固定习惯。执行频率支持每天、工作日（周一至周五）、自定义星期。
1. 每天根据当前日期生成当天应该执行的习惯任务。
2. 每天 00:00 后进入新的业务日期，新的任务初始状态为未完成。
3. 昨天未完成的习惯保留为未完成，不允许自动补签。
4. 修改习惯定义不影响过去的打卡记录。
5. 停用习惯不删除历史打卡数据。

### 4.2 临时任务管理
支持新增、修改、删除、完成和取消完成状态。临时任务只属于创建当天，不会自动延续到第二天；不参与固定习惯完成率计算；临时任务单独展示和统计。

### 4.3 每周训练计划
建议初始模板：周一上肢 A、周二下肢 A、周三有氧、周四上肢 B、周五下肢 B、周六有氧、周日恢复；用户可自行修改。
1. 固定训练计划按星期循环。
2. 用户可以修改长期每周训练模板。
3. 用户可以单独修改某一天的训练安排。
4. 单日修改不能影响其他日期和长期训练模板。
5. 修改固定模板时应记录生效日期，不能覆盖过去已经生成的安排。
6. 当天未训练时，可以标记为未完成或跳过。
7. 未完成或跳过不影响下一周的固定训练安排。
8. 默认每天一份主要训练安排，允许额外记录其他训练。

### 4.4 完整训练计划库
训练计划库与每周训练日程分离。一个训练计划代表一整次训练，例如肩部训练、胸部训练、背部训练、腿部训练或手臂训练；每套计划包含完整动作顺序及每个动作的目标组数、目标次数和目标重量。

1. 首次安装预置肩部、胸部、背部、腿部、手臂等完整训练计划。
2. 用户可以新建、修改计划名称/分类/说明，编辑计划内动作和目标数据，也可以删除计划。
3. 用户在某一天选择一套完整计划后，一次性导入该日期的主要训练安排，不需要每天逐个挑选动作。
4. 导入会替换当天尚未开始的主要训练动作列表；需要明确确认后执行。
5. 导入后的每日训练安排保存独立动作快照。之后修改或删除计划库模板，不影响已经导入的每日安排。
6. 当天开始训练时，仍从每日安排快照创建进行中训练；训练执行过程与正式历史规则不变。
7. 正式训练历史仍然独立保存动作及组数据快照，永久只读。

每周训练日程继续用于安排训练日、休息日和长期循环；完整训练计划库用于定义某一训练日实际要执行的整套动作。二者职责不同，不互相替代。

### 4.5 独立动作库
建立独立健身动作库，不将动作直接写死在训练计划中。可预置卧推、深蹲、硬拉、杠铃划船、高位下拉、肩推、侧平举等常见动作。支持搜索、新增、修改、删除。修改或删除动作库内容，不得破坏已经保存的历史训练数据。

### 4.6 训练执行与记录
用户在首页点击「开始训练」进入训练执行页面。每个动作记录动作名称、目标组数、目标次数、目标重量、每组实际重量、每组实际次数、每组完成状态。
训练过程中支持添加训练动作、临时增加动作、添加训练组、删除训练组、修改尚未完成的组数据、标记每组完成、自动保存训练进度。意外退出后恢复未完成训练。目标数据与实际数据必须分开保存，不能用计划重量代替实际重量。

### 4.7 训练历史管理
**正式保存的训练历史禁止修改、禁止删除，永久保留。**

| 训练状态 | 是否允许修改 | 是否允许删除 |
|---|---|---|
| 正在进行的训练 | 允许 | 可以放弃未完成训练 |
| 已完成并保存的训练 | 不允许 | 不允许 |

正式训练保存后：
1. 生成一条正式训练历史。
2. 保存训练日期、动作、组数、实际重量、实际次数等完整数据。
3. 历史记录只能查看，不能修改。
4. 历史记录不能删除。
5. 即使动作库中的动作后来被修改或删除，历史记录也必须保留当时的动作名称和训练数据。
6. 历史记录必须保存独立数据快照，不能只依赖动作库中的当前数据。

训练历史与动作库必须解耦。正式训练记录保存时，应将动作名称及必要信息复制到历史记录中。

### 4.8 历史与统计
V1.0 提供历史习惯打卡记录、历史训练记录、训练日期与训练内容查看、训练次数统计、连续打卡统计和基础训练数据统计。
统计口径：固定习惯完成率独立计算；临时任务独立统计；训练完成情况独立统计；不把临时任务和训练记录混入固定习惯完成率。

### 4.9 鼓励反馈
完成习惯或训练后，可以出现简单的鼓励弹窗。第一版不做复杂成就系统，但代码结构应保留以后扩展的空间。

## 五、数据库初步设计
| 数据实体 | 主要用途 |
|---|---|
| Habit | 固定习惯定义 |
| HabitRecord | 每日习惯打卡记录 |
| TemporaryTask | 每日临时任务 |
| WeeklyWorkoutPlan | 每周训练日程 |\n| WorkoutTemplate | 完整单次训练计划 |\n| WorkoutPlanExercise | 训练计划中的动作快照 |
| DailyWorkoutPlan | 每日训练安排 |
| Exercise | 独立动作库 |
| WorkoutSession | 一次实际训练 |
| WorkoutSet | 每组实际训练数据 |

还需考虑训练记录与训练动作的关联实体，以及未完成训练的自动保存和恢复机制。所有业务数据使用稳定 ID 关联，不得使用列表下标作为数据标识。正式训练历史需要保存动作快照，不能依赖动作库实时数据。

## 六、版本规划
| 版本 | 功能范围 |
|---|---|
| V1.0 | 习惯、临时任务、训练计划、动作库、训练记录、历史记录 |

## 七、V1.0 验收标准
- 能创建、修改和停用固定习惯。
- 支持每天、工作日和自定义星期。
- 日期切换后能够正确生成新一天的习惯任务。
- 昨天未完成的任务不会自动补签。
- 临时任务只属于当天，且独立统计。
- 能管理每周固定训练日程。\n- 能管理肩部、胸部、背部、腿部、手臂等完整训练计划。\n- 能将一整套训练计划一次性导入某一天。\n- 修改或删除计划库模板不影响已经导入的每日训练安排。
- 能单独调整某一天的训练安排。
- 能独立管理和搜索动作库。
- 能记录每个动作的实际组数、重量和次数。
- 训练过程中自动保存，退出后可以恢复。
- 能记录额外训练。
- 能标记训练未完成或跳过。
- 完成训练后生成正式历史记录。
- 正式训练历史不能修改，也不能删除。
- 动作库修改或删除不影响已有训练历史。
- 能查看历史习惯和训练数据。
- 完成任务后能出现鼓励弹窗。
- 本地 Room 数据库正常保存和读取数据。

## 八、开发实施顺序
1. 第一阶段：项目基础与页面框架——Compose 页面、底部导航、Material 3 主题、基础导航。
2. 第二阶段：固定习惯——习惯管理、频率设置、每日打卡、日期刷新、历史记录。
3. 第三阶段：临时任务——当日任务增删改查和独立统计。
4. 第四阶段：训练计划——每周模板、单日调整、未完成和跳过状态。
5. 第五阶段：独立动作库——动作搜索、新增、修改、删除。
6. 第六阶段：训练执行——训练页面、动作组数、实际重量次数、自动保存和恢复。
7. 第七阶段：训练历史——正式保存、只读展示、永久保留和数据快照。
8. 第八阶段：统计与体验优化——历史统计、鼓励弹窗、界面优化、完整测试。
